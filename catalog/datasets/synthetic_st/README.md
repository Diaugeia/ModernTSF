# synthetic_st

## Overview

`synthetic_st` generates its data in memory (seed 0, no file): each node has a daily sinusoid with a node-specific phase, a weekly modulation, and noise, and the item carries time-in-day and day-in-week covariates. Use it to check the spatiotemporal and covariate item contracts end to end; it has no adjacency and no real-world meaning.

## Provenance and license

- Generated by the loader code; no external source, no files, no license beyond the repository MIT license.

## Structure and statistics

| Item | Value | Basis |
| --- | --- | --- |
| Nodes | 8 (parameter `num_nodes`) | source-reported (loader default) |
| Length | 600 steps (parameter `length`) | source-reported (loader default) |
| Steps per day | 24 (parameter `steps_per_day`) | source-reported (loader default) |
| Channels | value + time-in-day + day-in-week | source-reported (loader code) |

Nothing is measured from files because the data are generated on demand; values are the loader's documented defaults.

## Standard protocol and known pitfalls

- Windows come from a 6:2:2 chronological split; validation and test start `seq_len` steps early for context. No scaling is applied.
- It supports the `spatiotemporal` and `covariate` task modes only, not plain `time_series`.
- Results are meaningless as accuracy; use it for shape and plumbing checks.
